# Reranker 三阶段微调流程设计

> 记录时间：2026-06-02
> 关联：train/listwise_awr/findings/reranker_awr_design.md、train/dpo/findings/score_based_dpo_design.md

## 1. 问题背景

DPO checkpoint-2000 的 val 结果显示：
- top-1 命中率有提升
- top-3/5 没有改善，甚至变差

根因分析：
- DPO 是 pairwise 信号，只学"A 比 B 好"，不学完整排序
- 模型把注意力集中在区分最好和最差，扰乱了中间档排序
- 同时发现 base model 存在大量打分错误（20% 正样本被低估，24% 负样本被高估）

## 2. 三阶段微调流程

```
Base Qwen3-VL-Reranker-8B
    ↓
阶段1: SFT（pointwise 纠错）
    ↓  修正模型的严重误判，打分校准变好
    ↓  数据: ~1988 条 hard examples（rank-based 冲突筛选 + 边界过滤 + per-query 上限）
    ↓
阶段2: DPO（pairwise 偏好精调）
    ↓  在已校准的基础上学"谁比谁好"
    ↓  数据: 等SFT跑完来选
    ↓
阶段3: Listwise AWR（listwise 排序优化）
    ↓  改善完整排序质量，特别是 top-3/5
    ↓  数据: 等DPO跑完来选
    ↓
最终模型
```

### 每阶段的分工

┌────────┬────────────────┬───────────────┬────────────────────────────┐
│ 阶段   │ 信号类型        │ 解决什么问题  │ 数据特点                    │
├────────┼────────────────┼───────────────┼────────────────────────────┤
│ SFT    │ pointwise 纠错  │ 打分校准      │ 精选 hard examples，量少质高│
│ DPO    │ pairwise 偏好   │ top-1 命中    │ chosen/rejected pairs      │
│ AWR    │ listwise 排序   │ top-3/5 排序  │ group + z-score advantage  │
└────────┴────────────────┴───────────────┴────────────────────────────┘

### 为什么这个顺序

1. **SFT 在前**：如果 base model 连基础的"相关/不相关"都判断错误，DPO 在错误的基础上学偏好效果打折扣。先纠错，给 DPO 一个更干净的起点。
2. **DPO 在中**：在已校准的模型上学 pairwise 偏好，直接提升 top-1。
3. **AWR 在后**：在 DPO 已经学好 top-1 的基础上，进一步用 listwise 信号优化完整排序。

## 3. SFT 样本构造：Rank-Based Hard Example Mining

### 为什么用 rank 而不是 sim 绝对值

初版方案用 sim 阈值（正样本 sim<0.30 / 负样本 sim>0.50）筛冲突，但分析发现模型打分整体偏低：

┌───────────────────┬────────┬──────────┬───────────┐
│ Bucket            │ 数量   │ sim 均值  │ rank 均值 │
├───────────────────┼────────┼──────────┼───────────┤
│ strong_positive   │ 2943   │ 0.44     │ 5.6       │
│ fallback_positive │ 3201   │ 0.40     │ 7.0       │
│ hard_negative     │ 11270  │ 0.36     │ 8.6       │
│ easy_negative     │ 20517  │ 0.28     │ 10.9      │
└───────────────────┴────────┴──────────┴───────────┘

strong_positive 的 sim 均值才 0.44，P25=0.38。sim<0.30 并不意味着模型"判断错了"，而是模型整体输出范围压缩在 0.2~0.5。用 sim 绝对值定义冲突不合理。

**rank 才是正确的冲突判据**：在同一 query 的候选池（~20个）里，正样本排到后半段（rank>10）才是真正的错排。

### 选定方案：Rank-Based 筛选 + 边界过滤

初版 rank-based 方案存在两个问题，经修正后定稿如下。

#### 修正 1：去掉 not_in_top20 样本

not_in_top20 的正样本是 embedding（bi-encoder）召回失败，不是 reranker 误判。
推理时 reranker 只重排上游 top20，这些样本根本不会进入 reranker 候选池。
拿召回失败的样本训练 reranker，等于教模型处理它永远不会遇到的输入，无意义。

去掉：strong not_in_top20 (131) + fallback not_in_top20 (216) = 347 条。

#### 修正 2：过滤 overall 边界样本

BCE 硬标签对边界样本太激进。分析发现：
- fallback rank>10 中 338 条 overall<4.0（占 44.7%），其中 174 条 <3.8
- hard_negative rank=1 中 35 条 overall>=3.5，14 条 overall>=3.8

一个 overall=3.6 的 fallback 硬推 target=1，一个 overall=3.4 的 hard_negative 硬推 target=0，
实际质量只差 0.2 但 loss 方向完全相反，会伤 NDCG。

过滤规则：
- 正样本只保留 overall>=4.0（去掉 338 条弱 fallback）
- 负样本只保留 overall<3.5（去掉 35 条边界 hard_negative）

这样正负之间 overall 至少差 0.5（4.0 vs 3.5），硬标签信号干净。
边界样本（3.5~4.0 区间）留给 DPO 阶段用 pairwise 信号处理更合适。

#### 修正 3：Per-Query 样本数上限

Pointwise SFT 容易被少数 query 带偏。分析发现：
- 正样本覆盖 456 个 query，mean=2.0 条/query
- 但 36 个 query 贡献了 5+ 条正样本，占总正样本的 24.3%
- 负样本天然每 query 最多 1 条（rank=1 只有一个 best_match），无需限制

限制每 query 最多 **3 条正样本 + 1 条负样本**，按强度优先选（strong 优先，overall 高的优先）。

┌──────────────┬────────┬────────┬────────┬────────────┐
│ 方案         │ 正样本 │ 负样本 │ 总计   │ 正负比     │
├──────────────┼────────┼────────┼────────┼────────────┤
│ 不限制       │ 903    │ 1223   │ 2126   │ 1:1.4      │
│ 3pos + 1neg  │ 765    │ 1223   │ 1988   │ 1:1.6      │
└──────────────┴────────┴────────┴────────┴────────────┘

选择 3pos：大部分 query 本来就 ≤3 条不受影响，只砍掉 63 个长尾 query 的多余样本（903→765，-15%）。

正负样本 overall 分布无重叠区间：正样本 >= 4.0，负样本 < 3.5，中间留出 0.5 的 gap。

### 为什么不用 rank>5

rank 6-10 的正样本模型还是给了中等排名，更像"排序不够精"而非"判断错了"。
SFT 的目标是纠粗错（打分校准），排序精度留给 DPO 和 AWR。
rank>5 会引入 3192 条正样本，混入大量信号较弱的样本，稀释信噪比。

### 为什么负样本只取 rank=1

rank<=3 的负样本有 4365 条，正负比会到 1:2.8，失衡。
rank=1 是"模型最看好的那个候选是负样本"，是最干净、最严重的误判信号。

### SFT 与 DPO 的分工

SFT 是 pointwise 的，只教"这个相关/不相关"：
- 纠正"模型把坏的排第一"和"模型把好的漏掉"这类粗错
- 不涉及候选之间的排序比较

DPO 是 pairwise 的，教"谁比谁好"：
- 在 SFT 校准后的基础上做精排
- 提升 top-1 命中率

每个阶段保持目标单一，样本干净不混。

## 4. SFT Loss

```python
# 输入: conversation(query + video_frames)
# 模型输出最后一个位置的 logits
score = logit_yes - logit_no

# 正样本: target=1 (yes), 负样本: target=0 (no)
loss = BCEWithLogitsLoss(score, target)

# 等价展开:
# 正样本 loss = -logsigmoid(score)     → 推高 score
# 负样本 loss = -logsigmoid(-score)    → 压低 score
```

## 5. 对比实验设计

最终需要对比的实验路线：

```
路线A: Base → DPO                         （已完成，作为 baseline）
路线B: Base → Listwise AWR                  （已准备好代码和数据）
路线C: Base → SFT → DPO                    （标准 RLHF pipeline）
路线D: Base → SFT → DPO → Listwise AWR     （完整三阶段）
路线E: Base → DPO → Listwise AWR           （跳过 SFT）
```

建议优先跑 C（SFT → DPO），与 A（已有的纯 DPO）对比，验证 SFT 纠错层是否有增量价值。
